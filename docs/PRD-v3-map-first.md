## 1. 产品定位与底线

### 1.1 定位

travel-frog 是一个**以地图为主视角的旅行回忆载体**。

产品围绕一面只属于用户的地图墙展开：照片按拍摄坐标钉在地图上，同一次旅行的站点被一条细线串起，青蛙替用户守着最近停下的地方。用户打开产品，是在一面墙上寻找某段已经发生的记忆，而不是管理尚未发生的行程。

产品单位是**一次旅行**，界面单位是**地图上的一个位置和它周围的照片**。

核心体验可以用一句话概括：**它替用户去过。**

### 1.2 产品底线

产品不做行程管理，也不做任何形式的管控或催促。以下机制在本版本中明确排除：

| 不做 | 说明 |
|---|---|
| 催办提醒 | 不提醒用户"还有待办"，不制造待处理的压力 |
| 打卡 | 不要求按地点、按天数完成签到 |
| 排行榜 | 不比较国家数、城市数、照片数，不做任何名次 |
| 额度任务 | 不设置"再传 N 张""再去 N 个城市"一类目标 |
| 出发推送 | 不推送"该出发了""很久没旅行了" |

产品的情绪目标是**安静的占有感**：打开或不打开都不产生负担，想起时它还在。

## 2. 地图墙

地图墙是产品的唯一全屏主界面，承载空间索引、阅读入口与整理操作。

### 2.1 空间层级

地图支持**世界 → 国家 → 城市**三级推近。

- 世界级：显示国家轮廓与各城市的照片堆，是默认视野。
- 国家级：显示更完整的城市标签与同城照片分布。
- 城市级：照片按拍摄点散开，站点之间的连线完整呈现。

缩放与平移不改变任何持久化数据。

### 2.2 照片、照片堆与连线

- 照片按拍摄坐标钉在地图上。
- 同一坐标范围内的照片聚成一个照片堆，堆上显示张数；点击后在原地散开。
- 同一趟旅行按站点时间顺序连线。
- 没有 GPS 的照片不钉在地图上，统一进入整理抽屉的补位置分区。

### 2.3 标签

- 地图上的标签为城市名与年份。
- 标签**自动避让**：按优先级贪心放置，空间不足时省略低优先级标签，不堆叠、不互相遮挡。
- 被省略的标签仍可通过点位清单访问。

### 2.4 点位清单

地图左侧提供点位清单，用于在不离开地图的前提下按年份、城市浏览全部点位。

- **收起态**：只保留一个 38px 的悬浮按钮，不显示整条白色横条，不占用地图面积。
- **展开态**：悬浮按钮展开为 300px 宽的分组面板，按年份与地区分组列出点位。
- 面板包含**「还想去」**分组，与已去过的地点并列呈现。
- 面板可随时收起，收起后回到单个悬浮按钮。

### 2.5 回忆浮层

点击地图上的照片堆或点位，打开回忆浮层。浮层在不离开地图的前提下展示：

- 该趟旅行的照片墙；
- 一句话记忆；
- 站点与时间；
- 大图查看；
- 跳转青蛙回放的入口。

浮层以遮罩覆盖地图，关闭后回到打开前的缩放级别与位置。

### 2.6 整理抽屉

从照片进入到档案正确之间的机械工作，统一收进右侧整理抽屉。抽屉包含四个分区：

1. **导入**：文件选择与拖拽导入，显示逐文件进度与结果。
2. **候选确认**：确认、合并、拆分、忽略自动切分出的候选旅行。
3. **补位置**：按本地日期分组，为缺少 GPS 的照片提供候选位置并支持按天套用。
4. **进度与失败**：列出进行中、已完成与失败任务，失败可重试并导出问题清单。

抽屉为非模态，打开时地图仍可读、可点；所有批量操作在写入前说明影响范围。

## 3. 明信片

明信片是"想去"在地图上的实物形态，与已去过的照片共享同一面墙。

### 3.1 五态状态机

明信片使用**显式五态状态机**，状态依次为：

```
托付 → 来信 → 掀开 → 盖戳 → 兑现
```

| 状态 | 含义 |
|---|---|
| 托付 | 用户把一个还没去过的地方交给青蛙 |
| 来信 | 青蛙带回一张写着话的明信片 |
| 掀开 | 明信片被从墙上掀下，翻到背面阅读 |
| 盖戳 | 这趟旅行被确认发生，明信片盖上邮戳 |
| 兑现 | 明信片转为地图上的已访问记忆 |

状态之间只允许按既定路径迁移。**任何非法迁移都直接报错**，不做静默纠正，也不根据界面操作猜测目标状态。

### 3.2 翻面交互

点击一张明信片，等于把它**从墙上掀下来、翻到背面**。

背面显示：

- 那趟旅行的照片；
- 日期；
- 坐标；
- 当时写下的话。

再次点击，明信片**钉回墙面**。

### 3.3 待定

世界视图下的明信片尺寸为 64px，「想去」邮戳偏小，本版暂未调整，列入待定项。

## 4. 青蛙

青蛙是地图与家中的角色层，不是独立页面。

### 4.1 在家落脚点

青蛙在家中有六个固定落脚点：

| 落脚点 | 状态 |
|---|---|
| 扶手椅一角 | 看地图 |
| 壁炉前地毯上 | 停留 |
| 多宝阁前 | 停留 |
| 明信片墙下矮书架边 | 停留 |
| 敞开的行李箱边 | 停留 |
| 落地灯旁脚凳上 | 打盹 |

屋内**永远只有一只青蛙**。

### 4.2 切换规则

- 进入家时，青蛙随机落在一个落脚点。
- 用户点击青蛙，它换到下一个落脚点。
- 用户点击某件陈列，青蛙走到与该陈列对应的位置。
- **它站在哪，就是在看哪。** 青蛙的位置本身就是当前的注意力指向。

### 4.3 明确不做

- 不做计时乱跑；
- 不做喂食；
- 不做好感度。

## 5. 青蛙的家

家不是第二个主界面，而是同一套系统的**里屋**：地图是外部的旅行世界，家是存放这些旅行的地方。

### 5.1 城市与搬家

- 默认家在北京。
- 家所在城市可以修改，也可以搬家。
- 搬家只改变地图上的房子标记位置；屋内陈列与全部历史记录保持不变。

### 5.2 北京的特殊处理

北京是家所在的城市，不作为旅行目的地参与统计：

- 不参与照片堆聚合；
- 不算旅行站点；
- 不计入国家数、趟数等任何旅行统计。

### 5.3 入口

入口有两处，且都刻意做得很弱：

1. **主路径**：地图上的小房子标记。它不参与照片聚合，也不被当作旅行点。
2. **次要入口**：地图之外的一个不显眼入口，例如点位清单底部。

首屏不出现「回家」按钮，不做角标提醒，不用红点或数字引导进入。

### 5.4 返回地图

从家返回地图时，必须恢复进入家之前的：

- 缩放级别；
- 平移位置；
- 点位清单滚动位置。

返回后不能重置到世界层级。

### 5.5 打开策略

家默认不打开。用户需要主动进入，产品不主动把家推到用户面前。

## 6. 家的陈列

家的画面是产品的视觉重心之一，但陈列只承担记忆与成长的表达，不承担操作密度。

### 6.1 三件主陈列

画面重心由三件主陈列构成：

1. **矮几上摊开的大幅世界地图**：四角用图钉固定，上面压着照片。
2. **扶手椅背后的明信片板**：明信片与旅行记忆集中陈列。

明信片板不是海报墙，也不是画廊网格。板上的对象就是地图上那批明信片，直接复用五态模型，**不为家新增状态**：

- 托付中：未寄出的空白卡，虚线纸边；
- 来信：已上墙、未盖戳，右上角一枚红点；
- 掀开：点击把卡掀下来翻到背面，读照片、日期、坐标与留言；
- 盖戳：邮票位置出现邮戳；
- 兑现：按年份归档到板子下沿的固定位置。

排列是生活化的：斜钉、叠角、被压住一半、空钉孔，不做整齐网格与画框。
3. **壁炉右侧的胡桃木阶梯式多宝阁**：特产一格一件。

### 6.2 背景元素

以下物件一律作为背景，只做色块与光源，不抢视觉重心：

- 壁炉；
- 深绿色布面单人扶手椅（不是双人沙发）；
- 波斯地毯；
- 落地灯；
- 边柜；
- 书架。

### 6.3 行李与成长刻度

行李是扶手椅右侧地面上一只**敞开的皮箱**，里面放着衣物与旅行帽。

皮箱尺寸即成长刻度：

| 去过的国家数 | 皮箱形态 |
|---|---|
| 不到 4 国 | 小手提箱 |
| 4 国起 | 标准旅行箱 |
| 8 国起 | 带外挂带与旅行贴纸的大衣柜箱 |

皮箱不做容量限制，永远不会装满，也不存在丢弃或取舍。

## 7. 养成层

养成层只记录已经发生的旅行，不引入游戏化数值。

### 7.1 特产

- 每个城市有 1–2 件特产。
- 只有去过才获得：照片与坐标落定即视为到过，特产随之出现。
- 不抽卡，不靠概率，不做随机掉落。
- 未获得时，多宝阁中只留**淡虚线轮廓**，不写字、不催促、不显示"还差几件"。

示例：

| 城市 | 特产 |
|---|---|
| 京都 | 折扇 |
| 里斯本 | 瓷砖片 |
| 伊斯坦布尔 | 香料袋 |
| 冰岛 | 黑石 |
| 曼谷 | 小铜佛 |
| 舍夫沙万 | 蓝染布 |

### 7.2 多宝阁

- 一格一件，已获得的特产按格陈列。
- 空格只显示淡虚线，不显示名称或数量。
- 点击特产可展开展示来历：来自哪座城市、属于哪一趟旅行、对应哪些照片。

### 7.3 家具生长

家具随行程兑现而生长，没有升级树，也没有货币。

| 条件 | 家中状态 |
|---|---|
| 不到 3 趟 | 扶手椅、地毯、明信片墙、摊开的地图、空多宝阁、空皮箱；壁炉不点火 |
| 满 3 趟 | 壁炉点火、边柜与圆镜出现、矮书架出现、皮箱装满 |
| ≥ 4 国且 ≥ 6 趟 | 落地灯亮起、地球仪出现、多宝阁八件特产摆满 |

家具变化只由已完成的行程触发，不由点击次数、登录次数或停留时长触发。

### 7.4 明确不做

- 货币；
- 经验条；
- 等级数字；
- 体力或冷却；
- 限时活动；
- 连续登录奖励；
- 好友来访；
- 舒适度、好感度等数值；
- 时间流逝：房间永远保持固定的午后光，不与本地时间同步；
- 背包容量与取舍。

## 8. 点击规则

家中与地图上可点击的对象只有三类，点击行为统一为"展开已有记忆"：

| 对象 | 点击后 |
|---|---|
| 明信片 | 从墙上掀下，翻到背面 |
| 特产 | 展开展示来历 |
| 地图 | 展开为可交互地图，并保留原缩放与位置 |

家中的明信片板与地图共用同一批明信片对象：点击只做翻面，不改变状态，也不产生新的明信片。

点击**只展开已经存在的记忆**：

- 不产生新资源；
- 不掉落物品；
- 不弹进度；
- 不出现「点 N 次解锁」。

## 9. 视觉规范

### 9.1 地图墙视觉规范

**地图墙保持当前 v3 实现的样子，不做写实化，也不做重纸纹改版。**

- 淡青灰绿水域 + 暖砂陆地、纸白卡片、极淡纸感；
- 顶部白底工具条；左侧浅米白面板按年份分组，城市后跟张数，底部「还想去」；
- 城市标签为白底细边小牌，只写城市、年份与张数；
- 照片堆为 2–3 张白边照片斜叠；
- 家的标记是地图上一枚很小的绿色房子图标，不加文字强调；
- 青蛙本体直接站在地图上，尺寸很小；
- 不使用写实海岸线、浮雕地形、照片级材质或明显纸纹/噪点。

视觉基准见 `prototypes/map/00-地图墙-基准.png`（现网地图墙截图）。

### 9.2 家的视觉规范

- 写实暗调：深绿色布面**单人扶手椅**是唯一座椅，不使用双人沙发；
- 房间只有壁炉火光与落地灯两处光源；
- 三件主陈列（矮几上摊开的世界地图、扶手椅背后的明信片墙、壁炉右侧多宝阁）是画面中仅有的被照亮区域；
- 四周为暗角，其他陈设退入阴影，只保留轮廓；
- 固定暖色午后光，不与本地时间同步，也不因点击改变光向。

家的场景原型待补，见 `prototypes/home/`（真实世界地图合成版主图）。

### 9.3 共用色板

| 用途 | 色值 |
|---|---|
| 纸底 / 面板 | `#F9F5ED`、`#FFFDF8` |
| 水域 | `#DDE6E4` |
| 陆地 / 暖砂 | `#E4DCCB` |
| 深绿强调 | `#1C5E36` |
| 浅尾灰绿 | `#C1D9CD` |
| 木框 / 深线 | `#5E432E` |

地图墙与家共用同一套暖色与胡桃木色：地图墙以水域色作纸白偏青的底、陆地色作暖砂；家以水域色作窗光与织物高光、陆地色作木面与纸张，木框色统一描边与家具暗部。

两套视觉并存、不互相改造：地图是扁平的纸质工具，家是写实的情绪场景，只共用暖砂、胡桃木与深绿这组颜色。

### 9.4 画面约束

- 全部画面为 16:9 横向。
- 不出现手机界面。
- 不出现文字标签、价格、等级数字。
- 视觉皮肤可以从扁平过渡到写实，但样式必须集中管理，不散落在结构与状态组件里。

### 9.5 原型图

原型图为设计依据，实现中视觉皮肤尚未替换。图片目录与清单见 `prototypes/README.md`。

- 角色：`prototypes/character/35-青蛙形象规范-1440.png`（三视图、六姿态、色号，1/4 椅高比例）
- 行李三档：`prototypes/growth/32-行李三档-1440.png`
- 地图墙基准：`prototypes/map/00-地图墙-基准.png`
- 家的场景：`prototypes/home/`（待补）

## 10. 技术与质量

### 10.1 领域层

- 领域层为纯函数，并显式维护不变式。
- 明信片五态状态机对非法迁移直接报错，不静默纠正。
- 旅行切分、站点聚合、统计等规则均在领域层完成，不依赖界面状态。

### 10.2 持久化

- 使用 IndexedDB 本地持久化。
- 数据库版本为 v4：v3 新增明信片五态，v4 新增 `home` 与 `mapView` 两个存储；升级采用**原地迁移**，不清库、不丢失已有档案。
- 家的城市、房子标记、青蛙落脚点、特产与地图视图（缩放、平移、点位清单滚动位置）均持久化。

### 10.3 质量门禁

- 当前测试用例数为 **70 个**，全部通过。
- 构建存在单 chunk 约 **523KB** 的体积提示；该提示为非错误告警，不阻塞构建。
- 提交前依次执行：

```bash
npm test
npm run build
npm run lint
```

三项全部通过方可合入。

## 12. 术语

- **地图墙**：唯一全屏主界面，包含地图、照片、照片堆、连线、标签、明信片与青蛙。
- **照片堆**：同一坐标范围内多张照片的聚合表示。
- **回忆浮层**：从地图上的一个点展开的阅读层，不是页面。
- **整理抽屉**：导入、候选确认、补位置、进度与失败的侧抽屉。
- **托付**：把未去的地点交给青蛙，是明信片生命周期的起点。
- **兑现**：明信片转为地图上的已访问记忆，是明信片生命周期的终点。
- **里屋**：家在同一套系统中的定位，不是独立主界面。
- **落脚点**：青蛙在家中的六个固定位置。
