# 蛙蛙自主旅行

2026-11-18。用户澄清：蛙蛙应能自己出门，不只等待指定目的地。本基线覆盖旧版新托付的固定6秒投递；旧档案仍兼容，不改写用户已收来信。

## 行为

- 初次打开即为蛙蛙安排一趟旅行，不需要个人照片或用户选择。默认从家休息约30–60分钟，之后收拾行李、去程、停留、返程。自然节奏一趟约数小时。
- 从14个内置故事城市中选择，排除家的城市和最近两站；优先选择没有有效明信片的地方。目的地、时刻、信件文本写入后不因刷新重新抽取。
- 自然节奏的去程/返程按离线坐标的远近给出约45–250分钟模拟时长，停留约45–135分钟。这些是游戏规则，不是实际航程、交通或天气数据。
- 自主旅行每三趟有一趟不寄信；其余在停留中段寄回一封。文本来自有限的离线虚构旅记，明显标注“模拟旅记”、趟数和自主/指定来源，不冒充实时观测或真人通信。
- 用户指定的方向在蛙蛙未出发时用于这一趟，已经出门时留作下一趟。只保留一个待执行方向，出发前可撤回。指定旅行承诺在停留时寄信，不采用固定6秒。
- 关闭自主出门会让在途的一趟走完；之后不再自己选择。用户仍能主动托付一趟，不会因此偷偷重开自主模式。尚未出发的托付可撤回。
- 加速演示明确标注，一趟约30–60秒，使用相同阶段及持久化状态机；不能把演示节奏当成自然旅行或真实后台智能体。改变节奏不改写已经出发的日程。

## 界面

页面持续提供“蛙蛙的旅行”入口，空档案也能直接查看。面板显示来源、路线、阶段、预计回家、来信状态与最近三趟旅记。家中出发前可见蛙蛙，出门后空出位置，返家后重新出现；地图只在当前视野包含模拟位置时呈现蛙蛙。

旅行不创建用户Trip、照片、到访统计或纪念品。收到的明信片沿用“留着／这次不去”，只有用户后来确认同城真实照片才可兑现。来信不要求用户定时领取。

## 离线和存储边界

没有服务器、后台Worker或通知。页面打开时按时刻推进；关闭后不执行。重开时只补算关闭前排定的这一趟（含当时尚未出发的计划），最多完成一趟并补记一封信；之后从重开时间重新安排，不凭空生成多趟历史。日程依赖设备时钟，清理浏览器数据会丢失记录，不同设备不自动同步。

IndexedDB v7只新增frogTravel存储，不重写v6照片、家或明信片。日程与来信在同一写事务中保存，日程行的版本条件在事务内校验；并发旧页面重读后重试，避免同一趟重复投递。最近12趟保存在旅记历史，已收到的明信片另在原档案中保留。旧版未投递的用户卡片继续走兼容流程；新托付有journey投递标记，明确排除旧6秒计时器。

搬家前未出发的日程从新家重新安排并保留托付；已经出门的一趟保留出发记录，归途朝当前的家恢复位置。未来三维房间与真实POI仍是独立草稿，不因本次自主旅行成为已验收功能。

## 验证

自动测试覆盖阶段和日程稳定、偶尔不寄信、长期离线仅补一趟、六秒不误投新卡、途中排队方向、关闭自主后回家停留、暂停时单次托付、撤回、搬家保留方向、两个页面并发一次投递，以及v6升级保留原记录。

真实浏览器使用本地HTTP、空白档案，未导入个人照片：自然节奏已自动排定；主动切换加速演示后，蛙蛙自行出门，家中角色消失，停留中收到首尔来信；途中托付会安成功成为下一趟方向，并在之后寄达。关闭页面130秒，重新打开仅新增关闭前这一趟的完成记录，没有补出多趟；之后才从重开时刻安排下一趟。暂停、回家见到蛙蛙和刷新恢复通过。暂停自主时主动托付仍保持关闭，待寄方向可撤回。

自然时光数小时的全程由可控时钟集成测试验证；浏览器完整流程使用明确标记的加速演示，未声称在真实浏览器中等待数小时。没有验证操作系统关闭浏览器后的后台通知，因为此版本不提供该能力。
