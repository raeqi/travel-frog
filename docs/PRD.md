# travel-frog 产品需求文档（v1）

> 一句话：**我的旅行档案，有只青蛙替我守着。**
>
> 文档状态：v1 已实现基线 · 最后更新 2026-11-17

## 1. 产品定位

travel-frog 是一个**私人旅行档案**，不是地图工具，也不是公开社交 feed。

它把手机里散落的照片，按时间和位置自动整理成一趟趟旅行（Trip），再用一只青蛙的视角把这些旅行讲回来：

- 照片是原料，**Trip 是核心单位**。
- 地图是**结果页**，不是入口。用户不是来查地图，而是来看"我去过哪里"。
- 不做公开主页、关注、点赞、排行榜。档案默认只属于用户自己。
- 不做导航、路线规划、机酒预订。它记录已经发生的旅行。

第一版只回答一个问题：**能不能在三分钟内，让用户长出第一趟旅行。**

## 2. 目标用户

- 手机里存着大量旅行照片，但从未系统整理过的人。
- 想回顾"这些年去过哪些地方"，又不想手动打卡、写长篇游记的人。
- 对隐私敏感，不愿意把原图、精确坐标上传到云端的人。
- 轻度旅行者与重度旅行者都适用：一年一趟也能用，一年十趟也不会乱。

典型场景：

1. 刚从一次旅行回来，想快速看到这趟的路线和照片。
2. 年底想回顾今年点亮了哪些城市、哪些国家。
3. 照片没有 GPS，想知道它们大概属于哪一趟、哪一天。
4. 想给某趟旅行写一句记忆，留给自己以后看。

## 3. 核心循环

```
导入照片 → 自动切分候选旅行 → 确认/合并/拆分 → 进入旅程详情
    ↑                                              ↓
    └──── 补位置 / 写记忆 / 看回放 / 点亮地图 ←────┘
```

1. **导入**：选择文件或拖入文件夹，本地读取 EXIF 时间与 GPS。
2. **切分**：按时间间隔、地理距离、连续天数生成候选 Trip。
3. **确认**：用户确认、合并、拆分、忽略候选；也可一键全部确认。
4. **回看**：站点时间轴、路线、照片流、一句话记忆。
5. **回放**：青蛙沿着路线逐站讲故事。
6. **补全**：给没有定位的照片按天找候选位置，批量补齐。
7. **点亮**：在我的地图上看到城市、国家的累计结果。

核心循环的每一步都必须在本地完成，不依赖账号、网络或云端。

## 4. 数据模型

v1 使用单一 `AppData` 结构，整体持久化到浏览器本地（IndexedDB）。

```ts
AppData {
  version: 1
  photos: Record<PhotoId, Photo>
  trips: Trip[]
  candidates: Candidate[]
  wishes: Wish[]
  manualVisited: ManualVisited[]
  settings: Settings
  config: SplitConfig
}
```

### 4.1 Photo

| 字段 | 说明 |
| --- | --- |
| `id` / `name` | 本地标识与原始文件名 |
| `takenAt` | 拍摄时间（EXIF，缺失时用文件修改时间兜底） |
| `lat` / `lng` | 精确坐标，仅本地使用 |
| `thumb` | 本地生成的小缩略图（约 320px JPEG） |
| `locationSource` | `exif` / `candidate` / `manual` / `none` |
| `tripId` / `visitId` | 归属的旅行与站点 |
| `ignored` | 是否被用户忽略 |
| `candidateId` | 补位置候选来源 |

### 4.2 Trip / Visit

- `Trip`：一次旅行的容器，包含 `title`、起止时间、`cityNames`、`visits`、`memory`。
- `Visit`：Trip 内的一个站点/城市片段，包含城市、国家、起止时间、坐标、照片数。
- 同一趟旅行内，同一城市只计一次，不按站点重复累计。

### 4.3 Candidate

候选旅行，是切分算法的输出、确认页的输入：

| 字段 | 说明 |
| --- | --- |
| `startAt` / `endAt` | 候选时间范围 |
| `photoIds` | 属于该候选的照片 |
| `cityNames` | 识别出的城市名 |
| `locationMissing` | 缺少定位的照片数 |
| `status` | `pending` / `ignored` |

### 4.4 SplitConfig

切分与站点聚合参数，均可在设置中调整：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `maxGapHours` | 30 | 相邻照片间隔超过该值则切分 |
| `maxDistanceKm` | 200 | 远距离跳变的判定阈值 |
| `farPlaceHours` | 8 | 远距离跳变需同时满足的最小间隔 |
| `maxTripDays` | 21 | 单趟最长连续天数，超过则在日界切分 |
| `visitRadiusKm` | 4 | 站点聚合半径 |
| `visitGapHours` | 6 | 站点内超过该时长无照片则结束该站 |

### 4.5 Settings

- `rawPhotoLocal`：原图是否只留在本机（默认开启）。
- `cloudSync`：云同步偏好（默认关闭，v1 不发起网络请求）。
- `cityLevelOnly`：云同步只允许城市级位置（默认开启）。

## 5. 关键流程

### 5.1 照片导入

- 支持文件选择与拖拽文件夹。
- 读取 JPEG/HEIC 的 EXIF：拍摄时间 + GPS。
- 无法解码的 HEIC 使用占位缩略图，不影响归档。
- **原图不上传、不复制出设备**，只在本地生成缩略图。
- 导入后立即按当前配置切分候选。

### 5.2 Trip 切分

纯函数实现，按拍摄时间排序后逐张判断：

1. 与上一张间隔 `> maxGapHours` → 新旅行。
2. 与最近一张有 GPS 的照片距离 `> maxDistanceKm`，且间隔 `≥ farPlaceHours` → 新旅行。
3. 距本段起点连续天数 `≥ maxTripDays` → 在日界切分。
4. 无 GPS 照片仍参与时间与天数规则。

切分结果生成候选，按时间倒序展示。

### 5.3 候选确认

每个候选展示：时间范围、照片数、城市、缺定位数。操作：

- **确认**：转为正式 Trip。
- **合并**：与相邻候选合并后重新计算城市与缺定位数。
- **拆分**：按指定时间点拆成两个候选。
- **忽略**：不进入档案。
- **全部确认**：一键处理所有 `pending` 候选。

### 5.4 旅程详情

三栏布局：旅程列表 / 站点时间轴与路线 / 照片流与一句话记忆。

- 站点时间轴：按时间排列，显示站点名、时间、照片数。
- 本地路线图：离线示意图，只显示当前站点标签，避免重叠。
- 照片流：本地缩略图，最多展示前 9 张。
- 一句话记忆：最多 60 字，只保存在本地，会出现在回放里。

### 5.5 回放

- 青蛙沿路线逐站移动，展示站点、时间、照片与记忆。
- 支持上一站 / 下一站 / 进度条与站点跳转。
- `Esc` 退出，键盘方向键切换站点。

### 5.6 我的地图

- 世界地图为国家轮廓的简化 SVG，内嵌离线数据。
- 点亮去过的城市，按国家聚合统计。
- 支持按年份筛选、按国家查看。
- 地图是结果页：从档案进入，而不是产品首页。

### 5.7 照片补位置

- 按天筛选缺定位照片。
- 同一天有 GPS 的照片按站点/地点分组求均值，生成候选。
- 没有同日候选时，回退到时间最近的有 GPS 照片。
- 支持一键确认单条、批量套用到当天、按时区修正时间、忽略。
- 所有写入只发生在本地。

### 5.8 青蛙页与缺口清单

- 青蛙页：用固定映射把城市转成小元素/记忆，属于 v1 的简化表达。
- 缺口清单：列出"去过但缺少照片/位置/记忆"的旅行，提示补齐。
- 缺口提示只做提醒，不阻塞主流程。

### 5.9 设置与隐私

- 原图不出设备（默认开启）。
- 云同步默认关闭；开启也只保存偏好，v1 不联网。
- 城市级位置开关。
- 导出 JSON：完整档案导出到本地文件。
- 删除全部数据：清空本地 IndexedDB，需要用户显式确认。

## 6. v1 范围与非目标

### 6.1 v1 范围

- 照片导入（文件选择 + 拖拽文件夹），本地 EXIF 解析。
- 自动切分候选 Trip，参数可配置。
- 候选确认页：确认 / 合并 / 拆分 / 忽略 / 全部确认。
- 首页与旅程列表。
- 旅程详情：站点时间轴 + 路线 + 照片流 + 一句话记忆。
- 回放：逐站 / 上下站 / 进度。
- 我的地图：点亮城市、国家统计、离线 SVG 世界地图。
- 照片补位置：按天筛选、候选确认、批量套用、忽略。
- 青蛙页、缺口清单、设置与隐私。
- 本地持久化（IndexedDB）。
- 示例数据一键加载，便于空态体验。

### 6.2 非目标（v1 不做）

- 公开社交 feed、关注、点赞、评论。
- 地图查询、导航、路线规划。
- 云端账号体系与真实云同步。
- 多人协作、共享旅行。
- 视频、Live Photo 的完整处理。
- 自动生成长篇游记或 AI 文案。
- 移动端原生 App。

## 7. 隐私原则

1. **本地优先**：照片、缩略图、精确坐标、旅行档案默认只存在本机。
2. **原图不出设备**：v1 不上传原图，也不把原图写入导出包。
3. **精确坐标不上云**：即使未来开启同步，也只允许城市级位置。
4. **云同步需显式授权**：默认关闭，开启是用户的明确动作。
5. **可导出、可删除**：用户随时导出 JSON，或一键删除全部本地数据。
6. **无暗默采集**：v1 不接入分析 SDK、不做行为上报。

## 8. 成功指标

### 8.1 核心指标

- **首趟旅行生成时间**：从导入到看到第一趟 Trip 的中位时长，目标 ≤ 3 分钟。
- **导入转化率**：进入导入页后成功生成至少一趟旅行的比例。
- **候选确认率**：候选被确认（而非忽略）的比例。
- **回访率**：7 天内再次打开档案的比例。

### 8.2 体验指标

- 补位置完成率：缺定位照片被补齐或显式忽略的比例。
- 记忆填写率：有记忆的 Trip 占比。
- 回放使用率：至少播放过一次回放的 Trip 占比。
- 地图查看率：进入过"我的地图"的用户占比。

### 8.3 质量指标

- 构建与单测通过。
- 关键流程无控制台错误。
- 本地数据在刷新后保持完整。

## 9. 版本与里程碑

- **v1（当前）**：完成上述范围，跑通"导入 → 切分 → 确认 → 详情 → 回放 → 地图 → 补位置"闭环。
- **v1.1（候选）**：更准的城市识别、更多图片格式、记忆模板。
- **v2（候选）**：在显式授权下的城市级云备份与跨设备恢复。
