# travel-frog v4：用户澄清与空间成长

2026-11-18，接在 `60c65e8` 的移动任务之后。本文记录用户最新确认，覆盖 v3 中与这些条目冲突的口径；其余本地档案、隐私、旅行切分和安静体验规则沿用。

## 用户已确认

- 所有青蛙由同一套形象演化，可以加入拟态动效；地图、插画房间和三维房间共用 `frog-poses.webp`，不另造角色。
- **家里的桌面地图是完整旅行地图的入口，不放明信片。** 完整旅行地图可以同时显示个人旅行照片与用户许愿后蛙蛙寄来的、用户标记的明信片；收到的来信也挂在家中墙上。
- 默认单人座椅，成长后家具增加、沙发可以扩大。家向可改变视角的三维空间发展，不锁定为永久固定机位。
- 纪念品按目的地扩展；只能依据实际旅行证据取得，不能通过点击生成。

## 本轮实际实施

### 地图和照片

- 修复城市照片内层 span 的零尺寸，保留原图颜色；保留移动任务已修复的透明蛙蛙按钮、地理层级和国家面包屑。
- 普通城市根据其照片坐标自动适配视野；不把京都的预制街道冒充其他城市的街道。普通城市当前仍使用国家轮廓与坐标网格，没有联网街道数据。追加直接拖拽、指针缩放、有限惯性与键盘操控；真实地点面板主动查询OSM，当前网络联调超时，成功链路未验收，详见实施记录。
- 个人照片不可用时显示明确的“照片暂不可用”，只有示例照片才使用示意插画。
- 新导入预览最大边从480提升至2048像素；不保存原图。已有480像素缓存不会凭空恢复清晰度，HEIC/HEIF解码仍由浏览器能力决定。
- 已兑现来信保持为带“去过了”标记的卡片，用户照片单独钉在地图。删去由随机种子生成的“兑现照片堆”，不把未存在的照片当作个人记忆。
- 保留新基底已有的“留着／这次不去”选择、迁移兼容和到访兑现规则，不回退到旧报告所依据的另一套按钮。

### 家、角色和收藏

- 保留插画房间、原移动时钟、绕家具寻路、空中目标排队、椅子起降与九姿态。
- 新增“环视房间”，提供真实几何体构成的开剖三维空间，可拖动左右视角、改变俯仰和缩放。点击地板投射到同一寻路坐标，桌面地图、来信和纪念品可点；也有键盘可访问的操作入口。
- WebGL可用时采用WebGL；不可用时采用相同几何和相机的SVG兼容渲染。兼容模式简化纹理与遮挡，没有关闭浏览器安全限制。
- 房间三阶段仍按既有旅行条件：基础、满3趟添置、至少4国且6趟齐全。三维座椅宽度分别2.1／2.7／3.3场景单位，始终处在原椅子障碍占位内；不把沙发扩大成会穿过寻路通道的新障碍。
- 新增目的地纪念品定义；未知目的地使用城市旅行牌。已有获得记录和来历保留。插画柜可翻页，每页8件；完整收藏可访问全部物件。三维超过8件增加边柜，全部收藏仍可通过清单阅读，不以收集进度催促。
- 墙上仅陈列已寄到、未放弃的来信；全部来信入口不再受到8张可见墙面布局限制。

### 整理和搜索

- 导入前先预览所选文件、大小和格式提示，再显式提交；支持文件夹选择与拖入目录的递归、分批读取。
- 导入阶段反馈包括元数据、预览、候选、保存；问题文件保留既有导出和重新选择重试机制。
- 候选拆分改为可拖动时间分界线，显示两侧张数，确认才写入。只提供不同拍摄时间之间的切点，防止空分段。
- 搜索支持上下键选择、回车跳转，大小写不敏感；保留Escape关闭。

## 明确的阶段边界

1. **已实现的空间第一阶段**：独立家具几何、有限左右环视（前方约±77°）、俯仰、缩放、共享寻路、三档座椅和阶段家具。插画视角保留参考图材质。
2. **后续资产阶段**：把几何代理家具替换成与参考图一致的写实模型、布料、皮革、木纹；把二维青蛙角色板升级为同一形象的多视角骨骼角色。目前不能称为写实三维成品。
3. **后续空间阶段**：更大房间、可走入的新增区域、任意摆放家具及动态导航网格、360°完整室内视野。当前新增边柜在已有不可走区域，未扩大导航面积；不会因收藏数量无限复制实体柜子。

三维相机与自由地板位置目前仅在当前访问保留；家具落脚点沿用原有持久化。没有新货币、等级、容量、登录任务或定时乱跑。

## 未在本轮宣称完成

- 原图保存、通用HEIC解码、联网通用城市街道图、全部设备的性能和可访问性审计。
- 未将旧1200主图、双人沙发三阶段板重新生成为新资产。旧图仅保留为历史证据；用户允许成长后扩座位，不代表这些旧图已是同机位成长素材。
